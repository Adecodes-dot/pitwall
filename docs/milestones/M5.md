## What was built
- **Onboarding wizard** (`ui/src/Setup.tsx`): 5 steps — game (auto-detected game is marked and pre-selected; Next needs a choice), in-game settings with the laptop IP as a copyable chip (F1) or "nothing to change" (GT7) plus the phone address, waiting-for-packets with a green light that auto-advances and a troubleshooting fold-out, radio check with "I heard it / Nothing" and the wired-earbud advice, GT7 assists (TCS 0–5, ASM, ABS, countersteer; F1 explains it is automatic), done. `firstRunDone` persists; the wizard stays available on the Setup tab.
- **Settings tab**: chattiness, mute, voice (lists `models/`), cloud phrasing (shows whether a key exists), laptop audio, GT7 packet format, units (km/h or mph, applied to the live view), record every session, crash logs, database path, version, "Show recent log". Changes apply live where possible; the tab says when a restart is needed.
- **Crash reporting** (`src/server/crash.ts`): session log + crash file with error, last 300 log lines, versions, OS; 14-day pruning; local only (D24). The shell offers Restart / Open logs / Quit when the companion dies.
- **Gamer docs**: `README.md` (install, two-minute first run, what the engineer says, FAQ with the five real failure modes, file locations, offline statement, credits).
- **Packaging** (`scripts/build-win.ts`, `app/main.cjs`, electron-builder config in package.json): UI build → esbuild server bundle (`dist/server/main.mjs` + `tts-worker.mjs`) → staged `dist/pkg` (bundle, UI, voice, native addons, `node.exe`) → smoke test (bundled server replays a capture, serves a debrief, TTS loaded) → NSIS installer. Electron main process spawns the bundled Node, waits for `/api/status`, opens the window and tray (Open, Logs folder, Quit); closing the window keeps the tray.

## Usability pass (first-time user, in-app browser, GT7 replay running)
Walked the wizard start to finish; what it surfaced and what changed:
1. Step 1 pre-highlighted F1 while GT7 packets were already arriving → now no pre-selection, the detected game is labelled "· detected" and pre-selected, Next is disabled until a game is chosen.
2. GT7 step 2 showed the laptop IP under "nothing to change" → moved the address to a "phone dashboard: open http://IP:8787" line; F1 keeps the IP chip beside the port.
3. Wizard buttons re-mounted on every telemetry frame (the Nav component was defined inside the render) → hoisted; buttons keep identity and focus.
4. Step 3 wording when nothing arrives ("Start a session on the PS5. Give it ten seconds." + fold-out) read clearly; kept. "Skip for now" lets a user without the console continue.
5. Radio check spoke through the laptop device and showed as the purple line; "I heard it" is a reassurance only (no logic hangs on it); kept.
6. Finish persisted `firstRunDone`, `game`, and the assists; verified via `/api/settings`.
Not changed but noted for the VM test: the firewall prompt appears when the companion binds its sockets, i.e. before the wizard reaches step 3; the README and step 2 both mention it.

On this network electron-builder's own downloads of its NSIS/7zip/winCodeSign tool archives from GitHub timed out twice (its `got` client; curl to the same URLs works). Workaround used: fetch the four archives with curl, serve them from a local static server, and point `ELECTRON_BUILDER_BINARIES_MIRROR` at it with `ELECTRON_BUILDER_BINARIES_ALLOW_HTTP=true`. Recorded in handoff.md; a one-off per machine because the archives are cached afterwards.
