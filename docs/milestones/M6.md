# M6 — First real session findings and hands-free voice (2026-10-26)

Trigger: the user's first real F1 25 career session (Shanghai free practice, PS5 over Wi-Fi, installed app). Reported: connection fine at first, then packet loss rose, fps fell, and the link dropped; 5 laps of data; request: talk to the engineer by voice with a wake word, no trigger commands, flexible language, hands on the controller.

## 1. What the session showed
Evidence available: the installed app's session log, its live `/api/status`, `/api/info`, `/api/settings` and `/api/debrief` (the process was still running), the shell log. No raw recording existed (recording was off), so packets could not be replayed.

| Observation | Meaning |
|---|---|
| Log: 5 laps, 99.226 / 97.437 / 98.046 / 98.131 / 98.537 s; a 6 minute wall-clock gap between laps 1 and 2 | Real laps were decoded (F1 2025/2026 Lap Data works). The gap is the outage the user described: lap 2's time arrived only when the stream resumed. |
| Status: "loss 33.8 %", last packet 565 s ago | The loss figure was a **lifetime total**, so the outage inflated it; it was misleading, not a measurement. |
| Debrief: "no completed laps yet", no new rows in the database | Laps never reached the analysis. Cause **not proven** (no capture). Fixed the two plausible causes and added diagnostics, see below. |
| Setup wizard not finished (`firstRunDone` false), mode set to Coach, 3 radio calls spoken | The engineer did speak (radio check and a few calls). |
| Laptop on a 5G mobile router (MTN-5G-4AFAF0) | Likely source of the drop-outs: mobile-network routers drop small bursty UDP and the PS5 reported disconnecting from Wi-Fi. F1 at 60 Hz is about 3 Mbit/s. |

## 2. Changes made because of it
- **Loss is now a rolling 10 s figure**, relative to the observed frame step (a 20 or 30 Hz send rate reads 0 %), ignoring outages over 1 s (counted as gaps). GT7 uses the game's packet id. Tests: clean 0 %, every 5th frame dropped reads 14–26 %, a 5 s outage reads 0 % with one gap, 30 Hz reads under 2 %, for both games.
- **Laps with a hole** (frame gap over 300 ms) keep the game's lap time but get no trace and cannot become the reference or train the track model. Test: a 3 s cut inside lap 3 → that lap flagged, others analysed, theoretical best still ≤ PB and within 3 %.
- **4 MB UDP receive buffers** (Windows default 64 KB holds about 10 F1 frames) and **event-loop lag measurement**.
- **Diagnostics line every 10 s** in the session log: packets/s, fps, loss, gaps, loop lag, frames accepted vs skipped off-track, bad-length packets. **Every adapter event** is now logged (stream found/lost, flags, safety car, session start/end, flashback), not just lap times.
- **F1 on-track also true when moving over 30 km/h**, so an unexpected driver/result status can never silently stop analysis and the radio.
- **Live recording on by default**: one `.pwcap` per session in `%LOCALAPPDATA%\PitWall\captures`, oldest pruned above 3 GB, so the next session can be replayed exactly.
- Network advice in the README: Ethernet for PS5 and laptop is the real fix; or 30 Hz send rate.

## 3. Hands-free voice (what was built)
- `src/voice/intent.ts`: natural-language matcher (no fixed commands). `src/voice/wake.ts`: wake gate. `src/voice/asr*.ts`: offline streaming recogniser in a worker. `src/voice/voice.ts`: listener (half-duplex, commands, follow-ups). `ui/src/mic.ts` + `Voice.tsx`: microphone capture and the card. Design and rejected alternatives: DECISIONS D27 and D28.
- Behaviour: "Engineer, how's my fuel?" / "…, where am I losing time?" / "How are the tyres, engineer?" / wake word alone then the question / follow-ups without the wake word for 7 s / "talk less", "more feedback", "normal mode" change and persist the chattiness / "say that again" / "mute", "talk to me". Beeps when the wake word is heard; stays deaf while the engineer talks; answers "Say again?" instead of guessing; ignores and discards everything not addressed to it.
- Removed the old push-to-talk (the browser's speech API sends audio to a cloud service in Chrome; the typed box remains).

## 5. Not verified, and risks
- **No real microphone, real voice, or room noise yet.** All speech here is synthetic (clean or with added noise). Expect real first-try accuracy below the 85–90 % above; the engineer says "Say again?" when unsure. First real hands-free test should run with `PITWALL_VOICE_DEBUG=1` so what it heard is in the session log.
- The packaged Electron window's microphone permission is implemented and syntax-checked; not exercised with a live device. Browsers block the mic on a plain LAN address, so a phone cannot be the microphone yet (needs HTTPS).
- Why laps did not reach the analysis in the Shanghai session is unproven; the next recorded session settles it.
- Wake word reliability is the weakest link ("engineer" was heard as "ineer", "er", "junior"); clipped forms are accepted only when the rest is a clear question. Follow-up (D29): the driver now chooses the engineer's name and teaches it by saying it five times; see DECISIONS D29 for the measured results (Bono and Will Joseph fine, GP weak on the synthetic voice).
