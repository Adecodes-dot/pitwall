# M3 — Radio: evidence (2026-10-16)

Scope (PRD §4): safe-zone detection, priority queue, deterministic call generator, TTS, chattiness modes, audio routing.

## Done condition
"Measured latency ≤ 300 ms p95 and a replayed session produces zero calls in braking zones (write the test for that)."

Status: **met on synthetic sessions.** Latency is measured on this laptop with the real voice and the real output device; the braking-zone rule is enforced by code and asserted by replay tests on both games.

## Latency (measured, not estimated)
`npm run latency -- --seconds 130` — real-time replay of a synthetic GT7 session, a yellow/green flag injected every 6 s at whatever track position the car is at, Piper voice bank, laptop output device (MME, 40 ms buffer). 21 safety calls spoken:

| Stage | p50 | p95 |
|---|---|---|
| trigger → call built | 0.0 ms | 0.0 ms |
| built → chosen (waiting for a safe zone; excluded from the budget by design) | 352 ms | 4196 ms |
| chosen → TTS ready (bank hit) | 0.0 ms | 0.4 ms |
| chosen → audio start (buffer handed to device) | 17.0 ms | 31.3 ms |
| + device buffer | 40 ms | 40 ms |
| **decision → sound** | **57 ms** | **71 ms** → PASS (≤ 300 ms) |

Full log: `m3-latency-run.txt`. The first 50 s run (before the track model existed, heuristic gating) gave p95 79.6 ms. Dynamic whole-sentence synthesis measures 136 / 167 ms p50 / p95 at 4 threads uncontended (`docs/research/tts-benchmark.md`); it is not on the time-critical path because coaching calls are synthesised at lap completion, a lap before they can be spoken.

Wired earbud from the laptop jack adds ~10–20 ms on top; Bluetooth would add 150–300 ms (RESEARCH.md §5). The phone page reports its own `AudioContext.outputLatency` back to the companion when "Play calls here" is enabled.

## Never in a braking zone
`src/radio/radio.test.ts` replays 4-lap synthetic sessions for F1 and GT7 with flags injected every 8 s and asserts, for every spoken call: brake pedal < 5 % at audio start; for calls gated by the zone map, the start position is in no braking zone and no corner of the *final* map built from every lap; before the model exists only safety calls are allowed and only with throttle > 80 % (straight heuristic). `npm run demo:m3` prints the same check on any capture:
```
7 calls spoken: 0 safety, 0 strategy, 4 coaching, 3 info
calls started inside a braking zone or corner: 0 PASS
dropped by persona rules: 0
```

## Audio routing (implemented)
- Laptop output device via a prebuilt MME addon, stream kept open all session (DECISIONS D17). Default.
- Browser playback: the PWA (phone or laptop page) receives WAV clips on the `audio` channel and plays them with Web Audio after one tap ("Play calls here"); it reports its output latency.
- Both can run at once; a wired earbud under the PS5 headset is the recommended setup (RESEARCH.md §5).

## UI
Radio tab: chattiness Quiet / Normal / Coach, "Play calls here", "Radio check", transcript with reason and latency. The last call is shown as a purple line under the status strip on every tab. Screenshot: `m3-radio.jpg`.
